# Conformance tooling (FR-2610-anvl-conformance-001)

Phase 0 of `roadmap-2610-anvil-js-parity.md`: P1 (`anvil-dump`), P2 (the corpus), P4 (the fuzz harness), P5 (drift tables).
Format and usage: `conformance/FORMAT.md`, `conformance/fuzz/README.md`.

## TDD record

1. Six hand-made inputs with expected dumps written by hand before the tool existed (`conformance/cases/handmade`),
   a stub `anvil-dump` that printed only its first line, and `make check-conformance`: **RED**, all 6 cases differing on
   the diff (the stub builds and runs; nothing else fails).
2. The tool, then GREEN. Four hand-written expectations were corrected on the merits, because native, not the
   author, is the spec: a statement has no source span of its own (the parser never fills `anvl_statement_t.span`),
   and an unterminated string is reported at the end of input (line 3, column 1), not at the opening quote.
3. The corpus was seeded afterwards and the dumps generated by native.

## Findings (native behaviour a port has to copy, or a defect)

- **No statement span.** `anvl_statement_t.span` is never set. The dump carries the spans of the name, base,
  attributes and values, and no statement span or text. If a statement span is wanted, it is a native change first.
- **Error name table.** `anvl_error_code_name(ANVL_ERR_IO_INVALID_PATH)` is `ANVL_ERR_FILE_INVALID_PATH`. The dump prints
  native's name; the drift table has the enum name. A port copies the dump.
- **BR-2610-anvl-001.** `include "."` and `include ""` reach `malloc` with a negative size in `files_load` (valgrind) and
  report `ANVL_ERR_MEMORY_ALLOC_FAILED` as an include error. Those two inputs are left out of the corpus on purpose.
- Newlines directly after `:=` are rejected ("Expected content"); whitespace rules are in the corpus, not written down.
- The `asl_function_decl_*` fixtures are dumped from the default build (`WITH_ASL=0`), so they record
  `ANVL_ERR_HEADER_ASL_NOT_SUPPORTED`. The corpus is for the ASL-off reader.

## Decisions

- The format is plain lines, not AML: a dump must stay readable when the parser under test is broken.
- When a load fails, only the error (and the dialect) is dumped: native's partial tree after an error is not behaviour.
- `anvil-dump` reads the real `anvil_document` through two hidden accessors (`include/internal/flat_internal.h`) rather than
  re-running the load pipeline, so it cannot drift from `anvil_load`.
- The seed scripts (`conformance/seed/*.py`) are one-shot and refuse to overwrite the committed corpus without `--force`;
  `check-conformance` needs only `sh`, `cpp` and `awk`.

## Memory incident (2026-10-30)

A 2M-case fuzz run grew to about 28 GB and the OOM killer took down the editor and every agent. The cause: a chain of
`$name` references that each name the previous one twice (`a1 := [$a0, $a0]; a2 := [$a1, $a1]; ...`) made the dump print
the resolved value under every reference, so 22 statements printed 3.7 GB and 40 would print 2^40 lines; the harness
read whole outputs into memory. Fixes: a `VARREF` now prints `resolved-doc`/`resolved-span` and not the expanded value
(FORMAT.md); the harness keeps at most jobs x 2 batches in flight, gives a child 1 GiB of address space and 64 MiB of
output, caps a case at 20,000 bytes and 6 levels, and drops every batch's state when the batch is compared. The doubling
chain is now a corpus case (`grammar/varref_chain_doubling.anvl`). Fuzz runs go in the foreground under
`systemd-run --user --scope -p MemoryMax=...` (STANDARDS section 8).
