A small, strict language for config and messages.

ANVL — Attributed · Node · Variadic · Language

ANVL is a text format with two dialects — AML for declarative modelling and configuration, and AMP for restricted, scalar-only messaging payloads. Anvil Native, the reference implementation, is a single C parser with no runtime dependencies — Node.js and WebAssembly bindings wrap it directly, so a document parses identically no matter which one reads it.

Why not just JSON?

JSON is a fine wire format. It's a rough config format — no comments, no way to reference a value you already defined, no restricted subset for contexts where a payload shouldn't be able to grow arbitrary structure. ANVL exists for the cases where those gaps actually cost you something.

JSONANVL
Comments Not allowed // and /* */
Reference a value you already defined Copy-paste, or a non-standard $ref convention Native $identifier, resolved once at parse time
Extend or override a template Not supported Single inheritance — Child : Base := {...}
A restricted subset for untrusted-ish payloads None — any valid JSON is valid JSON AMP dialect: scalars and flat arrays/tuples of them, no nesting, no objects — rejected otherwise at parse time
Metadata attached to a field Invent your own convention Native @[key=value] attributes
Bare identifiers as values Always quoted strings Unquoted wherever unambiguous

None of this is exotic on its own — TOML and YAML each solve pieces of it too. ANVL's bet is doing all of it under one strict, unambiguous grammar, plus a second, deliberately restricted dialect for when you want structure but not arbitrary structure.

Why ANVL

Grammar that doesn't guess

Most config formats are forgiving in exactly the wrong way — YAML's own "Norway problem" turns a bare no into the boolean false without asking, and you might not catch the silently wrong value for months. ANVL's grammar never guesses: a bare literal is only true, false, or null if it's exactly that word. Required statement terminators and no ambiguous comment characters close off the rest — a mistake fails to parse instead of quietly meaning the wrong thing.

Payloads that don't grow teeth

Message schemas start simple — a few scalar fields — and drift over time as someone nests a list inside a list, or slips in an object "just this once." Nobody reviews that drift until a downstream consumer breaks on structure it wasn't built to handle. AMP, ANVL's restricted dialect, allows scalars and flat arrays or tuples of them — nothing nested inside another collection, no objects, ever — enforced at parse time, not by convention or code review. The payload can't grow arbitrary structure even by accident.

Zero-copy, and nothing to attack

Anvil Native's internal state is integers — byte offsets and lengths into the buffer you hand it. No string is copied during parsing, and blob payloads are skipped entirely: the parser records where a blob starts and how long it is, then moves on without reading a single byte of its content. Under adversarial conditions — heap dump, memory probe, fuzzer — the parser can't expose payload data, because it never held any.

A look at AML

#!aml
server @[env = production] := {
    host := localhost;
    port := 8080;
    tags := [edge, cache];
};

// variables can be defined and referenced
var_ref    := 42;
derived_var := $var_ref;
