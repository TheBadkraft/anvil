One reference implementation, in C — bindings wrap it for other runtimes rather than reimplementing it. Pick what matches where your code runs.

Native library — C / C++

anvil-v0.11.0-rc-linux-x86_64.tar.gz — static (libanvil.a) and shared (libanvil.so) release builds, plus the public headers. Linux x86_64 only today; other platforms build from source until real cross-platform CI exists.
Download 
tar -xzf anvil-v0.11.0-rc-linux-x86_64.tar.gz
gcc your_program.c -I anvil-v0.11.0-rc-linux-x86_64/include \
    -L anvil-v0.11.0-rc-linux-x86_64/lib -lanvil -o your_program

WebAssembly — browser, or any JS host

anvil-wasm-v0.11.0-rc.tar.gz — the compiled module (dist/) and a JS-facing wrapper (lib/index.js), with the same API as the Node binding below, including types, schema and the writer, plus a prebuilt browser bundle (dist/anvil.browser.js) for a plain <script> tag. Runs on any WebAssembly host. Module loading is async (WASM instantiation) — see the bindings guide for the one-line difference.
Download 
const anvil = require('anvil-wasm');
await anvil.ready();
const doc = anvil.parse('#!aml\nfoo := 1;');
doc.get('foo').asInt(); // 1

In a browser, without a bundler:

<script src="/vendor/anvil/anvil.browser.js"></script>
<script>
  // anvil.wasm is fetched from next to the script; say where it is otherwise:
  anvl.ready({ wasmUrl: '/assets/anvil.wasm' }).then(() => {
    anvl.parse('#!aml\nfoo := 1;').get('foo').asInt(); // 1
  });
</script>

Node.js — N-API

anvil-node-v0.11.0-rc-linux-x86_64.tar.gz — a prebuilt native addon plus its JS wrapper. Same API as the WebAssembly binding above (synchronous, no ready() needed). Linux x86_64 (glibc) only today; not published to a package registry, so install it from the tarball and build other platforms from source.
Download 
const anvil = require('anvil-node');
const doc = anvil.parse('#!aml\nfoo := 1;');
doc.get('foo').asInt(); // 1

.NET — C#

anvil-net-v0.11.0-rc-linux-x64.tar.gz — a prebuilt managed assembly (Anvil.Net.dll) built directly on Anvil Native's vtable ABI, plus the native library it links against. Linux x64 (glibc) only today. There is no NuGet package, so reference the assembly directly; other platforms build from source.
Download 
using var doc = AnvilDocument.Load("config.anvl");
var server = doc.FindValue("server");
server["port"].AsInt(); // 8080

Python — ctypes

anvil-py-v0.11.0-rc-linux-x64.tar.gz — a pure-ctypes binding built directly on Anvil Native's vtable ABI, plus the native library it links against. No compiled extension module. Linux x64 (glibc) only today; not on PyPI, so put the extracted src directory on PYTHONPATH; other platforms build from source.
Download 
tar -xzf anvil-py-v0.11.0-rc-linux-x64.tar.gz
export PYTHONPATH="$PWD/anvil-py-v0.11.0-rc-linux-x64/src:$PYTHONPATH"
with AnvilDocument.load("config.anvl") as doc:
    server = doc.find_value("server")
    server["port"].as_int()  # 8080

Verify any download with SHA256SUMS (sha256sum -c SHA256SUMS in the folder holding the files). Every file reports the version 0.11.0-rc+316. The native downloads (C library, Node.js, .NET and Python) are Linux x86_64 only; the WebAssembly build runs anywhere WebAssembly does.

Previous release: v0.10.0-rc — C library, WebAssembly, Node.js, .NET, Python (SHA256SUMS-v0.10.0-rc).

Full usage guide for every binding is in Docs → Bindings; what changed in this release is in the Changelog. This is release-candidate software — the format and API are stable enough to build against, but expect the surface to keep moving before a 1.0 release.
