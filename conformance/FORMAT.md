# The anvil-dump format, version 1

`anvil-dump` prints a canonical, deterministic description of what Anvil Native parsed. The conformance
corpus (`conformance/cases/`) holds one dump per input, generated by native. Any implementation of the reader
(anvil.js) must print the **same bytes** for the same input. That is the whole contract: a port compares its
own dump with native's, byte for byte. Native is the spec. When a dump and a port differ, the port is wrong
unless an owner decision changes native first.

The format is a **contract**. It is versioned: the first line is `anvil-dump 1`. A change to what a dump
contains, or to how a line is written, bumps the version, regenerates the whole corpus, and is a deliberate
act (`make update-conformance`), never a side effect.

Revision history of this document (the dump version is the number on the first line; a revision that only
makes the text exact does not change it):

- **Version 1, first text**: the Phase 0 format.
- **Version 1, second text** (FR-2610-anvl-conformance-002): the same bytes, specified without gaps: the
  `dialect` line on an error, the exact number rules, the document identity and the walk, the path rule, how
  line and column are counted, the batch protocol (moved here from `fuzz/README.md`), and the limits native has.
  No dump of the 1165 earlier cases changed. The version stays `1`.

## Why a line format, not AML

The format has to be readable when the implementation under test is broken. A dump written in AML would need
a working AML parser to read the very output that checks the parser. The format is therefore plain lines of
`word key=value` tokens: trivially diffable, trivially parsed from any language (split on spaces outside
quotes), and independent of the grammar being tested.

## Lexical rules

- Output is ASCII, `\n` line endings, no trailing whitespace, no blank lines, a final newline.
- A line is a *record name*, then space-separated *fields*. Nesting is two spaces of indent per level.
- A field is `key=value`. A value is one of:
  - an integer (`12`, `-7`), a bare word (`ASSIGN`, `true`, `none`), a hex literal (`0x4004000000000000`);
  - a **quoted string** `"..."`;
  - a **span** `start-end`: half-open byte offsets (`end` exclusive) into the source buffer of the document
    the node belongs to, counted from 0. `none` means the node has no position.
  - a **hex string**: lowercase hex digits, two per byte, possibly empty (`bytes=`).
- A **quoted string** is written byte by byte: `\\` for a backslash, `\"` for a quote, `\n`, `\r`, `\t`, and
  `\xHH` (lowercase hex) for every other byte below `0x20`, for `0x7f`, and for every byte from `0x80` up.
  Every other byte is itself. Strings are length-delimited, so NUL (`\x00`) and non-UTF-8 bytes are ordinary.

## Records, in order

```
anvil-dump 1
mode document|fragment
input-bytes N
status ok|error
dialect AML|AMP|ASL|ERROR         (document mode, when the root document exists; see below)
```

then either the error records (when `status error`) or the tree (when `status ok`).

`mode fragment` is the input parsed as a standalone value expression (`anvil_parse_value_fragment`); it has no
`dialect` line and, when `status ok`, a single `value` record (with its children) at indent 0.

### The `dialect` line

In `mode document` the line is written **whenever native created the root document, whatever the status**: on
`status ok` and on `status error` alike. It is left out in `mode fragment`, and in the one document-mode case
where native failed before it had a root document (a root file that cannot be read: its error is the `code=0`
record described below). Its place is always right after `status`, before the first `error` or `doc` record.

Its value is the dialect native had determined for the **root** document at the point it stopped (an error in an
included document does not change it):

1. start from the extension hint of the root file: `.amp` gives `AMP`, `.asl` gives `ASL`, anything else (`.anvl`,
   `.aml`, no extension, an unknown one) and a buffer read from stdin give `AML`;
2. a shebang overrides it. A shebang is `#!` and **exactly three bytes** (`aml`, `amp` or `asl`, lower case),
   after optional leading space, tab, CR or LF; whatever follows those five bytes is ordinary content (`#!amlx := 1;`
   is `AML` followed by `x := 1;`; `#!aml trailing` is `AML` followed by the content `trailing`);
3. a shebang that is not one of those three words, or that is shorter than five bytes (`#!`, `#!am`, `#!AML`, `#! aml`,
   `#!xyz`), makes the dialect **`ERROR`**: native's dialect-detection error state. It always comes with
   `error code=2011` (`ANVL_ERR_PARSER_INVALID_SHEBANG_DIALECT`, line 1, column 1) and never with `status ok`. `ERROR`
   is not a dialect a document can have, only the value of this line (and of nothing else: a `doc` record in the
   tree never carries it).

So a dump can say `status error` with `dialect AML` (the usual syntax error), with `dialect AMP`, with `dialect
ASL` (native built without AnvilScript refuses `#!asl` with `error code=2012`, and the line still says `ASL`), or
with `dialect ERROR`. A port must print the dialect of the shebang or the extension even when the parse fails
later. Cases: `coverage/errors/shebang_*`.

`input-bytes` is the number of bytes of input read. The tool never reports file names, so a dump does not
depend on where the corpus is checked out.

### Errors (`status error`)

```
error code=5002 name=ANVL_ERR_PARSER_UNTERMINATED_STRING category=4 category-name=ANVIL_ERR_SYNTAX line=3 column=1 message="Unterminated string literal"
```

One line per error native recorded (native records the first one only, so in practice one). `code` is the
internal `anvl_err_code` number (`include/errors.h`) and `name` is native's name for it
(`anvl_error_code_name`; note it is native's table, which for `1003` says `ANVL_ERR_FILE_INVALID_PATH`).
`category` is the public `anvil_err_code` (`include/anvil_types.h`): `0` OK, `1` IO, `2` HEADER, `3` INCLUDE,
`4` SYNTAX, `5` RESOLVE, `6` MEMORY, `7` INVALID_ARGUMENT. `line` and `column` are 1-based as native reports
them (`0` when there is none). `message` is native's message text, exactly.

**Line and column.** A line break is the byte `\n` and nothing else: `\r`, `\r\n`'s `\r`, form feed and vertical tab
are ordinary bytes (a document with lone-`\r` line ends is one line). `line` is 1 plus the number of `\n` before the
error position; `column` is 1 plus the number of **bytes** between the last `\n` (or the start) and the error
position. So a tab counts as 1, a two-byte character as 2, a three-byte one as 3, a four-byte one as 4, an invalid
UTF-8 byte as 1, a NUL as 1, and a byte-order mark is three ordinary bytes (a BOM before the first statement is
itself a syntax error, at line 1, column 1). No UTF-8 decoding takes place anywhere. The error position is the
start of the token native was reading when it failed (for `5.` and `1e`, the first digit of the number; for an
unterminated string or blob, the end of the input); a port reports the same position, not the position it would find natural. In an included document the
line and column are those inside the included document, and the dump does not say which document it was.

When a load fails, **nothing but the error is defined**: no tree is dumped, because the partial tree native
leaves behind is an implementation artifact, not behaviour a port should copy. If native failed before it
recorded anything (an unreadable file), one line `error code=0 name=ANVL_ERR_NONE ...` with the public
category and an empty message is written (and no `dialect` line, see above). The corpus holds no such case,
since an input is always an existing file; the line exists for completeness.

Two errors depend on the resolved include path (see **Includes**): an include whose joined path is 1024 bytes
or longer is `error code=9002 name=ANVL_ERR_INVALID_ARGUMENT category=3` (an include category, not an argument
category), and a file that cannot be opened is `error code=4204` (`ANVL_ERR_INCLUDE_FILE_NOT_FOUND`).

Most error codes in `include/errors.h` can never be produced from a document: see `notes/conformance-error-coverage.md`
for the list of the codes the corpus reaches (41) and why the others cannot be.

### The tree (`status ok`)

One `doc` record per **distinct document**, numbered from 0 in the order below; the root is `doc 0`.

**The walk.** Start at the root. To visit a document: if it is already numbered, stop; otherwise give it the next
number, then visit, in the order the `include` declarations appear in its source, the document each one resolved
to, each visit finishing (with everything below it) before the next sibling starts. That is a depth-first,
pre-order walk with the document numbered when it is first entered and an include's own subtree dumped
before its next sibling. It is not breadth-first: with `root` including `a` then `b`, `a` including `c`, and `b`
including `d` then `c`, the numbering is `root 0, a 1, c 2, (c's own includes), b, d`, and `c` is not repeated under `b`
(`coverage/includes/walk_root.anvl`; reverse the first two includes and the numbers change,
`walk_root_reversed.anvl`). A document that is reached again (a diamond, a shared leaf, a cycle that native
accepts) is not dumped again; the `include` record that reached it carries `resolved=<its first number>`, which may
be a smaller number than the current document's own. The `doc` records are then printed in number order.

**What "the same document" means: identical bytes.** Native identifies a document by a hash of its source bytes
(64-bit FNV-1a), not by its path. Two includes that name *different paths* with *byte-identical contents* (a
copy of a file, an empty file named twice) resolve to the **same** document, which keeps the path of the first
one reached (`coverage/includes/identical_copies.anvl`). An include of a file whose bytes equal the root's resolves to
`doc 0` (`self_dot.anvl`). A port compares the bytes (a hash collision between different files is outside the
contract). Which of two spellings of one path is "first" is decided by the walk above.

**Cycles.** An include that names, **by exactly the same joined path string**, a document still being loaded
(one of its ancestors in the include chain) is `error code=4206` (`ANVL_ERR_INCLUDE_CYCLIC`) and the load fails
(`self_exact.anvl`, `mutual_a.anvl`). The comparison is textual: `"./self.anvl"` against `"self.anvl"` is not
the same string, so the include is accepted, the bytes are the same, and it resolves to the existing document
(`self_dot.anvl`, `mutual_dot_a.anvl`: the dump then shows an include that resolves to a document with a smaller number).

```
doc 0 path="<root>" dialect=AML bytes=132
  attr ...                        module attributes, in source order
  include ...                     includes, in source order
  stmt ...                        top-level statements, in source order (repeated names stay repeated)
doc 1 path="f01_bare_literal.anvl" dialect=AML bytes=205
  ...
```

`path` is `"<root>"` for the root. For an included document it is the path native opened, with the root
document's directory prefix removed. Native opens `<directory of the including document>/<the include string>`
(an include string starting with `/` is opened as it is), **without normalising it**: `.` and `..` segments, repeated
slashes and a `./` prefix stay as written. The including document's directory is its own path up to its last `/`
(`.` when it has none), so a document in `sub/` that includes `"s2.anvl"` opens `<root dir>/sub/s2.anvl` and one
that includes `"../x.anvl"` opens `<root dir>/sub/../x.anvl`, printed `sub/../x.anvl`. The dump is made from
inputs run by their path relative to `conformance/cases/` (see **Corpus layout**), so the root directory prefix is
`<group>/` or `<group>/<dir>/`; a root named with no `/` at all (a bare file name, or stdin, whose directory is `.`)
prints its includes with a leading `./` (`./x.anvl`). Absolute include paths print as they are and are not used
by the corpus, since they would depend on the machine. `bytes` is its source length.

**include**: `include decl-span=7-38 decl="include \"x.anvl\"" path-span=15-38 path="\"x.anvl\"" resolved=1`.
`decl` is the declaration without its `;`; `path` is the path literal with its quotes. `resolved` is the index
of the `doc` it resolved to.

**`resolved=none` cannot occur in a dump.** A tree is only dumped for `status ok`, and native loads every include of
a successful load: an include that cannot be resolved (missing file, unreadable file, joined path of 1024 bytes
or more, cycle, a failing included document) fails the whole load with an error and no tree. The value `none` is kept in
the grammar for a port's own use and is never produced by native. The unresolved-include behaviour that *is*
specified is the error dump (`coverage/includes/missing_*.anvl`, `failing_child_*.anvl`, `path_len_*.anvl`).
The cases `coverage/includes/path_len_1005.anvl` and `path_len_1006.anvl` sit on the length boundary for a root run as
`coverage/includes/<file>` (the joined path is 17 + 1 + len(name) bytes: fine up to 1005, too long from 1006);
a name of 1024 bytes or more is too long wherever the root is.

**stmt**: `stmt kind=ASSIGN name="x" name-span=6-7 base="" base-span=none attrs=0`. `kind` is `ASSIGN`,
`OBJECT_BLOCK`, `VARS`, `IMPORT` or `FUNCTION` (the last two only with AnvilScript). `base` is the
inheritance base name (`""` and `none` when absent). `attrs` is the number of attribute records that follow.
Native records no source span for a statement as a whole, so none is dumped; the spans of its name, base,
attributes and value are. Children, indented one level: the `attr` records, then the statement's `value`
(an `OBJECT_BLOCK` has an `OBJECT` value, as the flat API reports it).

**attr**: `attr key="a" key-span=24-25 raw="1" raw-span=26-27 flag=0`. `raw` is the attribute's value text as
written, `flag=1` (and `raw-span=none`) for a flag attribute with no `=value`. Its child, when it has a value,
is the **decoded** value (a `value` record, indented one level): the attribute value read as a value, so
`@[status="done"]` has a `STRING` child, `@[range=1..5]` a `BARE` one.

**value**: `value type=T span=a-b text="..."`, then fields by type. `text` is the exact source text of the
value's span (the contents only for a string and a blob; no delimiters):

| type | extra fields |
|---|---|
| `NULL`, `BARE` | none |
| `BOOL` | `bool=true\|false` |
| `NUMERIC` | `kind=integer\|float overflow=0\|1`, then `i64=<n>` (integer, no overflow) or `f64=0x<16 hex digits>` (float, no overflow); with `overflow=1` neither is written. The exact rules are in **Numbers** below |
| `STRING` | `decoded="..."`: the string after native's escape resolution (`\n \t \r \\ \"`; any other backslash pair is kept as written) |
| `BLOB` | `tag="..." tag-span=a-b bytes=<hex>`: the tag (`""` and `none` when untagged) and the content bytes |
| `ARRAY`, `TUPLE`, `OBJECT` | `count=n`; the children follow, one level deeper: `value` records (array, tuple) or `stmt` records (object) |
| `VARREF` | `target="name" public=T resolved=0\|1`; when resolved also `resolved-doc=N resolved-span=a-b`: the document index and span of the value it resolved to, which is dumped where it is declared (it is not repeated under the reference, or a chain of references would print exponentially many lines) |
| `FUNCTION`, `NONE` | none |

`VARREF` is the one place the tree is not the public view: native's accessors see through a resolved `$name`
(`public=` is the type they report; an unresolved reference reports `NULL`). An `OBJECT` that inherits from a
base lists the inherited fields too, after the object's own, exactly as native resolved them; their spans point
into the document where they were written.

## Numbers

**Which text is a `NUMERIC` value.** The word starting a value is a number when it matches, in this order,

```
number   = [ "-" ] digit+ [ "." digit+ ] [ ( "e" | "E" ) [ "+" | "-" ] digit+ ] boundary
boundary = end of input | " " | tab | CR | LF | ";" | "," | "]" | ")" | "}"
```

Anything that is not followed by a `boundary` is not a number but a longer word, and becomes a `BARE` value
(`1_000`, `0x10`, `12abc`, `1d`, `1-2`, `1.2.3`, `1e5.5`, `5.x`, `1/* c */`, and `.5`, which does not start with a digit);
`NaN` and `Infinity` are bare words too. Two shapes are committed to being numbers and are **errors**: a `.` not followed by a digit
when what follows is a boundary or an exponent (`5.`, `5.;`, `5.e3`) is `error code=5009 ANVL_ERR_PARSER_INVALID_NUMBER`, and an `e`/`E` not followed by digits
when a sign follows it or a boundary does (`1e`, `1e+`, `1e-`, `1e;`) is `error code=5008 ANVL_ERR_PARSER_INVALID_EXPONENT`.
A leading `+` is not part of a number (`+5` is `error 2003`); a word starting with `-` that is not a number (`-.5`, `-a`, `-1a`, a lone `-`) is `error 2003 ANVL_ERR_PARSER_EXPECTED_VALUE` too, not a bare word. Leading zeros are
part of the number (`007`, `-0009`, `00.5e0`).

**`kind`.** `integer` when the text contains none of `.`, `e`, `E`; otherwise `float`. (`12e3` is a float.)

**Integer, `kind=integer`.** The text is `["-"] digit+`. The value is the decimal number it spells (leading zeros do
not count, so `0000000000000000000000000007` is 7 and a 400-digit run of zeros followed by 5 is 5; `-0` and `-000`
are 0). It is **`overflow=1` exactly when it is outside the signed 64-bit range**, that is when the magnitude is
greater than 9223372036854775807 for a number without `-`, or greater than 9223372036854775808 for one with `-`:

| text | result |
|---|---|
| `9223372036854775807` | `i64=9223372036854775807` |
| `9223372036854775808` | `overflow=1` (no `i64=`) |
| `-9223372036854775808` | `i64=-9223372036854775808` |
| `-9223372036854775809` | `overflow=1` |
| `0009223372036854775807`, `-0009223372036854775808` | `i64=` the value (padding is ignored) |
| `0009223372036854775808`, `18446744073709551615`, `1` followed by 99 zeros | `overflow=1` |
| `-0`, `-000` | `i64=0` (an integer has no negative zero) |

**Float, `kind=float`.** The value is the double nearest to the exact decimal number the text spells, **correctly
rounded to nearest, ties to even**, as a C library's `strtod` does in the default rounding mode, for any number of
digits (a 100000-digit mantissa is exact, not truncated at 17 digits). The dump writes the 64 bits of that
double: `f64=0x` and 16 lower-case hex digits, sign bit first (so `-0.0` is `0x8000000000000000`). A float is
**`overflow=1` exactly when that rounding gives infinity**, and for no other reason. Infinity is the result when
the magnitude is **at least 2^1024 - 2^970**, the midpoint between the largest double and 2^1024 (a midpoint rounds
to even, which is infinity). In decimal that is the 309-digit integer
`179769313486231580793728971405303415079934132710037826936173778980444968292764750946649017977587207096330286416692887910946555547851940402630657488671505820681908902000708383676273854845817711531764475730270069855571366959622842914819860834936475292719074168444365510704342711559699508093042880177904174497792`
(`1.79769313486231580793...e308`). The sign does not matter (`-1e999` overflows too).

| text | result |
|---|---|
| `1.7976931348623157e308` (the largest double) | `f64=0x7fefffffffffffff` |
| `1.7976931348623158e308` | `f64=0x7fefffffffffffff` (still below the midpoint) |
| `1.7976931348623159e308`, `-1.7976931348623159e308` | `overflow=1` (above the midpoint) |
| 2^1024 - 2^970 written in full with `.0`, and that plus one | `overflow=1` |
| the same minus one, with `.0` | `f64=0x7fefffffffffffff` |
| `1e308` | `f64=0x7fe1ccf385ebc8a0` |
| `2e308`, `1e309`, `1E309`, `1e+309`, `1e999`, `1e1000000`, `1e99999999999999999999` | `overflow=1` |
| `1e+0000000000000000000000000000000000000308` | `f64=0x7fe1ccf385ebc8a0` (leading zeros of an exponent do not count) |
| `1` followed by 309 zeros then `.0` | `overflow=1` |

**Underflow is never overflow.** A magnitude too small for a double rounds to a subnormal or to zero, keeps its sign, and has `overflow=0`:
`5e-324` is `0x0000000000000001`; `2.4703282292062327e-324` (below the midpoint to the smallest subnormal) is
`0x0000000000000000`; `2.4703282292062328e-324` (above it) is `0x0000000000000001`; `1e-999`, `0e99999999999999999999` and `1e-99999999999999999999` are
`0x0000000000000000`; `-1e-999` is `0x8000000000000000`; `-0.0` and `-0e5` are `0x8000000000000000`.
An exponent with more digits than any integer type holds is read as an arbitrarily large exponent, never as an error
and never wrapped: it overflows a non-zero mantissa and gives zero for a zero mantissa.

`i64=` is written with no sign for positive and `-` for negative, in decimal, with no padding and no `+`.
Corpus: `coverage/numbers/` (about a hundred spellings, one per file), and the earlier `grammar/` numbers.

## Strings

`decoded=` is the string with native's escape set resolved: `\n` (10), `\t` (9), `\r` (13), `\\` (`\`) and `\"` (`"`), and
nothing else. Scanning is left to right and every backslash is looked at once: a backslash followed by one of those
five bytes is replaced by the byte; **any other backslash pair stays as two bytes** (`\x41`, `\u00e9`, `\0`, `\/`,
`\'`, `\T`, a backslash and a multibyte character). A backslash that was
consumed as the first half of `\\` is not looked at again, so `\\t` is a backslash and the letter t, `\\\t` is a
backslash and a tab, and five backslashes then `t` are two backslashes and a tab. A raw tab, CR, LF, NUL or any other byte
inside the quotes is an ordinary content byte (a string may span lines). The raw text is always in `text=`.
Corpus: `coverage/escapes/` and `grammar/`.

## Limits native has

- **No nesting limit is defined.** Arrays, tuples and objects nest to any depth that native's recursion can
  hold. Native is recursive and has a C-stack limit: on the default 8 MB stack it handled 40000 levels of arrays or tuples and 25000 of objects, and crashed with a
  stack overflow at 60000 and 30000 (`ulimit -s unlimited` removes the crash); that is a defect, not a rule, and
  a port must not copy it. The corpus goes to 400 levels (`coverage/nesting/`), which every port must handle.
- **Include path length**: see **Includes**: a joined path of 1024 bytes or more is `error 9002`.
- No limit on identifier length, string or blob length, number length, statement count or element count has been found
  (`coverage/errors/name_very_long.anvl`, `string_very_long.anvl`, `many_statements.anvl`, `numbers/digits_*`).

## Corpus layout

```
conformance/
  FORMAT.md               this file
  drift-tables.txt        enums, keywords and tokens extracted from include/*.h (see below)
  cases/<group>/<input>   an input
  cases/<group>/<input>.dump   native's dump of it
  seed/                   the scripts that seeded the corpus (output committed; not run at check time)
  fuzz/                   the differential fuzz harness
```

- An input is any file under `cases/` that is not a `.dump`. It is run from `cases/` by its relative path, so
  `include` resolves there. A `.frag` input is dumped with `--fragment`; the file extension of every other input
  is the dialect hint native uses (`.amp` for AMP).
- Groups: `handmade` (written before the tool, TDD), `fixtures` (a verbatim copy of `test/fixtures`; the check
  fails if the two differ), `unit` (the inline inputs of the unit tests, extracted), `grammar` (generated
  from tables: numbers, strings and escapes, blobs, attributes, empty and one-element rules, statement
  forms, includes, errors), `coverage` (FR-2610-anvl-conformance-002, generated by `seed/gen_coverage.py`:
  `includes/` the include graph, `nesting/`, `columns/` multibyte, tab, CR and BOM error positions, `escapes/`,
  `numbers/` every overflow boundary, `errors/` the remaining error codes and the shebang forms).
- A case that is **not an error** is as binding as one that is: several `coverage/errors/` inputs look wrong and
  native accepts them (a duplicate attribute key, a keyword as an attribute name, a duplicate object field, a
  reference to a name that does not exist). The dump is the specification of what is accepted.
- `AnvilScript` statement kinds (`VARS`, `IMPORT`, `FUNCTION`) and `#!asl` documents are **not** in the corpus: the
  corpus is generated with a native built without AnvilScript (`WITH_ASL=0`), where `vars` and `import` are keywords and
  `#!asl` is an error.
- `cases/writer/` is the writer corpus (see "The writer script" below): its inputs are `.wscript` files, run with
  `--writer-script`, and are not dialect hints. `cases/builder/` is the builder corpus ("The builder script"): `.bscript`
  files, run with `--builder-script`.
- `make check-conformance` regenerates every dump and diffs it with the committed one: **any difference
  fails**, as does an input without a dump or a dump without an input. `make update-conformance` rewrites them;
  use it only alongside a deliberate native change, and commit the new dumps in the same commit.

## The writer script, version 1

The reader half of the corpus is `anvil-dump 1`. The **writer** half is a second, separately versioned contract:
a **writer script** (`anvil-writer-script 1`) names a sequence of writer API calls with literal arguments, and
native's run of it (`anvil-writer-run 1`) is the exact bytes the writer produced, or the error it returned. An
implementation of the writer (anvil.js) runs the same scripts through its own writer and must print the **same run,
byte for byte**. Native is the spec; when a run differs, the port is wrong unless an owner decision changes native
first. A change to the script grammar or to the run format bumps the number, regenerates the writer corpus and is a
deliberate act. (FR-2610-anvl-conformance-003.)

The writer surface is `include/anvil_writer.h`. A script drives one writer from `anvil_writer_new` to
`anvil_writer_data`; the writer is disposed when the script ends.

### The script

A script is a byte file of `\n`-terminated lines. The generated corpus is ASCII, but any byte is legal inside a quoted
string (below).

1. **Line 1** is exactly `anvil-writer-script 1`.
2. A blank line, or a line whose first non-blank byte is `#`, is ignored. A `#` is a comment only at the start of a line.
3. Every other line is one **step**: a *call name*, then its *arguments*, separated by spaces or tabs. Leading and
   trailing blanks are ignored. The step's number is its **1-based line number in the file** (comments and blank lines
   count); the run reports it as `line=`.
4. The first step other than `option` is `dialect`, and no other step is `dialect`.

An **argument** is a *word* or a *quoted string*:

- a **word** is a run of bytes up to the next blank; it contains no `"`. The words used are `NULL`, `true`, `false`,
  `AML`, `AMP`, option names, and numbers.
- a **quoted string** is `"` ... `"`. Inside, a byte `0x20`-`0xff` other than `"` and `\` stands for itself (so raw UTF-8
  is allowed), and these escapes are recognised: `\\`, `\"`, `\n`, `\r`, `\t`, `\xHH` (two hex digits, either case).
  A raw byte below `0x20`, an unknown escape or a missing closing quote is a script error. `\x00` is allowed: the
  string is length-delimited. The closing quote is followed by a blank or the end of the line.
- A string argument is the **decoded bytes**. Where the C parameter is a NUL-terminated `const char *` (a name, key,
  path, tag, base, value, numeric text, bare text), the string must not contain `\x00`. Where the parameter is a pointer
  plus a length (`string`, `blob` content, `attribute_string` text), the length is the decoded byte count.
- **`NULL`** (the bare word, never the quoted string) is the null pointer, for a pointer parameter.
- A **count or length** is a decimal integer.

**Calls.** One call per API function; arguments are all required unless shown in `[ ]`.

| call | arguments | native function |
|---|---|---|
| `dialect` | `AML` \| `AMP` \| *integer* | `anvil_writer_new` (an integer is the raw enum value, to reach an invalid dialect) |
| `option` | `on-error stop` \| `on-error continue` | (script control, see below) |
| `get_error` | | `anvil_writer_get_error` |
| `error_message` | *integer* | `anvil_writer_error_message` (any integer, in or out of range) |
| `attribute` | *key*, *value* (string or `NULL`) | `anvil_writer_attribute` |
| `attribute_string` | *key*, *text* [, *len*] | `anvil_writer_attribute_string` |
| `include` | *path* | `anvil_writer_include` |
| `statement` | *name*, *base* (string or `NULL`) | `anvil_writer_statement` |
| `null` | | `anvil_writer_null` |
| `bool` | `true` \| `false` | `anvil_writer_bool` |
| `numeric` | *text* | `anvil_writer_numeric` |
| `int` | *int64* (decimal, optional `-`) | `anvil_writer_int` |
| `double` | see below | `anvil_writer_double` |
| `string` | *text* [, *len*] | `anvil_writer_string` |
| `bare` | *text* | `anvil_writer_bare` |
| `blob` | *tag*, *data* [, *len*] | `anvil_writer_blob` |
| `varref` | *name* | `anvil_writer_varref` |
| `begin_array`, `end_array`, `begin_tuple`, `end_tuple`, `begin_object`, `end_object` | | the function of that name |
| `finish` | | `anvil_writer_finish` |
| `data` | | `anvil_writer_data` |

- `string`, `attribute_string` and `blob`: the optional *len* passes a length **shorter** than the string (a prefix is
  written); it may not exceed the decoded length unless the string is `NULL`, where *len* is passed with the null pointer
  (`string NULL 3` is `anvil_writer_string(w, NULL, 3)`). Without *len*, the length is the decoded length, or `0` for `NULL`.
- `double` takes one of: a **decimal**; **`0x` and exactly 16 hex digits**, the IEEE-754 bits of the double (this is how
  `-0` and every exact value are written: `0x8000000000000000`); or the words `nan`, `inf`, `-inf`. The exact rules
  are under "Input rules" below.
- An *integer* argument of `dialect` or `error_message` is a decimal with an optional `-`, within `int32` (the C `int` of
  the enum).
- `option on-error continue` makes the run go on after a failed call (default `stop`); it can appear anywhere, even before
  `dialect`, and takes effect from the next step. It counts as a step in `steps`. It is a script directive, not a writer call.
- A writer call that returns `false` is **failed**. `dialect` fails when `anvil_writer_new` returns `NULL`; the writer
  is then `NULL` and every later call is made with a `NULL` handle (it fails with `ANVIL_WRITER_ERR_INVALID_ARGUMENT`).
  `get_error`, `error_message`, `data` and `option` never fail.

**Input rules.** What the tool accepts and rejects, so a port need not guess:

- **Blanks** are the space and the tab, nothing else. In a step line, leading and trailing blanks are ignored. The
  **header line** is compared exactly: `anvil-writer-script 1` and nothing before or after it (a leading or trailing
  blank, space or tab, is a script error at line 1).
- **Line endings** are `\n` only. `\r` is not a blank and not a terminator: a CRLF script fails at line 1 (the header
  line then ends in `\r`); in a later step line a `\r` stays part of the last word (`finish\r` is an unknown call,
  `dialect AML\r` an invalid dialect word); a raw `\r` inside a quoted string is a script error (write `\r` or `\x0d`);
  a comment line may contain one. The **last line need not end in `\n`**: it is a step like any other.
- **`int`** (and the integer of `dialect` and `error_message`): an optional `-`, then one or more decimal digits, nothing
  else, within `int64` (`int32` for the two enum-valued calls). Leading zeros are allowed and mean nothing (`007` is 7,
  `-007` is -7) and `-0` is 0. A leading `+`, a hex form (`0x10`), an empty or a fractional number is a script error;
  so is a value out of range.
- **`double`, decimal form**: a non-empty word made only of the characters `0-9 . e E + -` that C's `strtod` (the `C`
  locale) converts **entirely**, correctly rounded. So `+1.5`, `.5`, `5.`, `1e5`, `1E+5`, `-0` (negative zero),
  `1e-999` (underflows to `0`) are accepted; `-`, `.`, `e5`, `1e`, `1e+`, `1-2` are script errors. A decimal that
  overflows (`1e999`, `-1e999`) is **not** a script error: it converts to infinity, reaches the writer, and the call fails
  with `ANVIL_WRITER_ERR_INVALID_NUMERIC` like `inf`. The bit form is `0x` in lower case and exactly 16 hex digits (digits
  of either case): `0X3ff0000000000000` and `0x1` are script errors. The words are exactly `nan`, `inf` and `-inf`, in
  lower case: `-nan`, `+inf`, `NaN`, `Infinity` are script errors. Every non-finite value (the three words, the
  non-finite bit patterns, an overflowing decimal) fails at the writer, never at the tool.

A **script error** (an unknown call, a wrong argument count or kind, a bad string, a number out of range, a missing
`dialect`) is not a writer outcome: the tool prints the message and the line to stderr, nothing to stdout, and exits 2.
The corpus holds no script error.

### The run

`anvil-dump --writer-script <file>` prints, to stdout, ASCII with `\n` line endings, in this order. Quoted strings are
written exactly as in the reader dump (see "Lexical rules": `\\ \" \n \r \t`, `\xHH` lowercase for every other byte
below `0x20`, for `0x7f` and from `0x80` up).

```
anvil-writer-run 1
<records, one per event, in execution order>
steps N
status ok
output bytes=N text="..."
```

- **`get_error code=C name=NAME`** for each `get_error` step. `C` is the `anvil_writer_err_code` value (`0` is
  `ANVIL_WRITER_OK`), `NAME` its enum name.
- **`error_message code=C text="..."`** for each `error_message` step; `text` is `anvil_writer_error_message(C)` (a
  value outside the enum gives `unknown error`).
- **`data none`** or **`data bytes=N text="..."`** for each `data` step: what `anvil_writer_data` returned at that
  point.
- **`failed line=L code=C name=NAME call="..." message="..."`** for each failed call. `L` is the step's line number;
  `call` is the step's line **verbatim** with leading and trailing blanks removed, quoted; `C` and `NAME` are
  `anvil_writer_get_error` right after the call (the first error is sticky, so in continue mode every later failure
  repeats the first code); `message` is `anvil_writer_error_message(C)`.
- **`steps N`**: the number of steps executed (the failing one included; steps after a stop are not counted).
- **`status ok`**, or **`status error code=C name=NAME`**: `anvil_writer_get_error` at the end.
- **`output bytes=N text="..."`**: the bytes of `anvil_writer_data` after the last executed step, when it returned
  non-NULL, with `N` its length (the terminating NUL is not counted); else **`output none`**. Output exists only after
  a successful `finish` and no later error. `N` is the byte count: it is what makes a mismatch obvious, and a port
  compares `text` as raw bytes.

`anvil-dump --writer-output <file>` prints only the output bytes, raw, and exits 0; with no output it prints nothing
and exits 1. `scripts/check-writer-roundtrip.sh` uses it.

### The writer corpus

`conformance/cases/writer/<area>/<name>.wscript` is a script and `<name>.wscript.dump` is native's run. The scripts
are **generated** by `conformance/seed/gen_writer.py`, which writes scripts only. The runs are **native's**: `.dump`
files are written by `make update-conformance` and by nothing else, as for every other expected dump in the corpus. The
generator also holds a small model of the canonical layout (3-space indentation, `name := value;` per line, `a, b`
separators) that computes the run each script should give; it is a **cross-check, not a source**
(`gen_writer.py <root> --force --check-model <anvil-dump>` lists every case where native differs from it, and
`make check-writer-gen` requires none). `make check-conformance` checks, for every `.wscript`, that native's run equals the
committed `.dump` (the same rule as the reader cases), and `make check-writer-roundtrip` checks that **every successful
output loads through the native reader with `status ok`** (an `include` is satisfied with an empty file of that name).
A case whose output the reader rejects is a writer/reader inconsistency, not a corpus fault; it is listed with its
ticket in `conformance/writer-roundtrip-known.txt` (empty today). `gen_writer.py` changes the scripts and
`make update-conformance` then rewrites the dumps. A port compares its own run of each `.wscript` with the `.dump`.

Areas: `lifecycle` (new, finish, data, get_error, error_message, sticky errors), `scalars` (null, bool, `int`, `numeric`,
`double`), `strings`, `bare`, `blobs`, `collections` (arrays, tuples, objects, nesting), `attributes`, `statements`,
`include`, `varref`, `amp` (the AMP dialect and what it refuses), `envelope` (King & Crucible messages).
Every `anvil_writer_err_code` the flat writer can return has a case; `ANVIL_WRITER_ERR_MEMORY` and
`ANVIL_WRITER_ERR_DEPTH_EXCEEDED` cannot be reached through the flat writer (the latter belongs to `anvil_builder`), so
they appear only through `error_message`.

## The builder script, version 1

The builder is the third contract of the corpus. A **builder script** (`anvil-builder-script 1`) names a sequence of
`anvil_builder_*` calls (`include/anvil_builder.h`) with literal arguments, and native's run of it
(`anvil-builder-run 1`) is every failed call, every `find` result, the exact bytes of every `emit` and `write`, and the
final status. An implementation of the builder (anvil.js' `AnvilBuilder`) runs the same scripts through its own builder
and must print the **same run, byte for byte**. Native is the spec. A change to the grammar or the run format bumps the
number and regenerates the corpus. (FR-2610-anvl-conformance-004.)

The builder differs from the writer in three ways the format has to carry: values are **handles** (a node or a member
is created by one call and used by later ones), errors are **not sticky** (a failed call changes nothing and the next
call works), and the output comes from an explicit `emit` or `write` step, as many times as the script likes.

### The script

The lexical rules are **the writer script's**, unchanged: the same bytes, lines, comments, blanks, quoted strings and
escapes, `NULL`, step numbers (the 1-based line number), the same `int` and `double` forms, `option on-error`, and the
same script-error conditions. The **header line** is exactly `anvil-builder-script 1`. The first step other than
`option` is `dialect`, and `dialect` appears once.

A **step** is

```
[let NAME =] [other] CALL ARGS...
```

- **`let NAME =`** binds the call's result to the handle `NAME`. `let`, `NAME` and `=` are separate words (`let x=null`
  is a script error). Only the calls marked *node* or *member* below return something to bind. `NAME` is
  `[A-Za-z_][A-Za-z0-9_]*`, and is not `NULL`, `true`, `false`, `let` or `other`. A name may be bound again; the latest
  binding wins. A call that returns a handle without `let` is legal (the handle is dropped).
- **`other`** makes the call on the **second builder** instead of the first (not for `dialect`, `builder2`, `option` or
  `error_message`, which are script errors with `other`). It is how a script reaches the
  foreign-handle error (a node from one builder given to another).
- A **handle argument** is a bound name, or the word `NULL` (the null handle). A quoted string in a handle position is a
  script error. A name used before it is bound is a script error, and so is a handle of the wrong kind (a member where a
  node is expected, or the reverse). The kind of a name is the kind of its latest `let`, known without running the script.
- If a call that has a `let` **fails**, the name is bound to the null handle. (Later calls that use it get a null
  handle, and fail the way the C function does.)
- Handles and their builder: a node or member belongs to the builder that made it. Handles of builder 1 and of builder 2
  live in one namespace.

**Calls.** `P` text pointer (a quoted string without `\x00`, or `NULL`); `S` bytes (a quoted string or `NULL`) with an
optional length; `N` a node handle, `M` a member handle (a bound name or `NULL`); `I` an integer.

| call | arguments | result | native function |
|---|---|---|---|
| `dialect` | `AML` \| `AMP` \| *integer* | | `anvil_builder_new` (builder 1; an integer is the raw enum value, to reach an invalid dialect) |
| `builder2` | `AML` \| `AMP` \| *integer* | | `anvil_builder_new` (builder 2, for `other`; once, after `dialect`) |
| `option` | `on-error stop` \| `on-error continue` | | script control, as in the writer script |
| `get_error` | | | `anvil_builder_get_error` |
| `error_message` | *integer* | | `anvil_writer_error_message` (the builder reports the writer's codes) |
| `attribute` | *key* `P`, *value* `P` | | `anvil_builder_attribute` |
| `attribute_string` | *key* `P`, *text* `S` [, *len*] | | `anvil_builder_attribute_string` |
| `include` | *path* `P` | | `anvil_builder_include` |
| `null` | | node | `anvil_builder_null` |
| `bool` | `true` \| `false` | node | `anvil_builder_bool` |
| `numeric` | *text* `P` | node | `anvil_builder_numeric` |
| `int` | *int64* | node | `anvil_builder_int` |
| `double` | as the writer script | node | `anvil_builder_double` |
| `string` | *text* `S` [, *len*] | node | `anvil_builder_string` |
| `bare` | *text* `P` | node | `anvil_builder_bare` |
| `blob` | *tag* `P`, *data* `S` [, *len*] | node | `anvil_builder_blob` |
| `varref` | *name* `P` | node | `anvil_builder_varref` |
| `array`, `tuple`, `object` | | node | `anvil_builder_array`, `_tuple`, `_object` |
| `append` | *collection* `N`, *element* `N` | | `anvil_builder_append` |
| `add` | *object* `N` (`NULL` is the document), *name* `P`, *value* `N` | member | `anvil_builder_add` |
| `set_base` | *member* `M`, *base* `P` | | `anvil_builder_set_base` |
| `member_attribute` | *member* `M`, *key* `P`, *value* `P` | | `anvil_builder_member_attribute` |
| `member_attribute_string` | *member* `M`, *key* `P`, *text* `S` [, *len*] | | `anvil_builder_member_attribute_string` |
| `find` | *object* `N` (`NULL` is the document), *name* `P` | member | `anvil_builder_find` |
| `emit` | | | `anvil_builder_emit` |
| `write` | [`AML` \| `AMP` \| `NULL`] | | `anvil_builder_write` into a fresh writer, then `anvil_writer_finish` (below) |

Every `S` and *len* rule, and the `int` and `double` forms, are the writer script's (`string NULL 3` passes the null
pointer with the length 3; a *len* longer than a quoted string is a script error). The builder has **no removal or
replacement call**: a node is attached once and a statement is added once.

- **`write [W]`** makes a fresh writer of dialect `W` (default: the dialect of the builder the call is made on; `AML`
  when that builder is the null builder), calls `anvil_builder_write(builder, writer)`, and if it succeeds calls
  `anvil_writer_finish` and reads `anvil_writer_data`. `write NULL` passes the null writer. A `W` that differs from the
  builder's dialect is legal; native's result is the spec. The writer is disposed at the end of the step.
- A call is **failed** when it returns `false`, when a constructor, `add` or `emit` returns `NULL`, when `dialect` or
  `builder2` yields no builder, or when `write` succeeds but its `finish` fails. **`find` never fails**: it returns a
  member or `NULL`, and it does not change the builder's error. `get_error`, `error_message` and `option` never fail.
- After a failed `dialect` the builder is the null builder, and every later call on it is made with a null handle (it
  fails with `ANVIL_WRITER_ERR_INVALID_ARGUMENT`, and `get_error` on it is that code).
- `option on-error continue` behaves as in the writer script. Because builder errors are not sticky, a later call
  works normally. **`get_error` reports the outcome of the most recent call** on that builder (`find` excepted).
- The builder's output is **borrowed**: an `emit` record is printed when the step runs, so a later call cannot change it.

The depth limit is `ANVIL_BUILDER_MAX_DEPTH` (256) containers; exceeding it fails the `emit` or `write` with
`ANVIL_WRITER_ERR_DEPTH_EXCEEDED`. A **script error** is as in the writer script (stderr, exit 2, nothing on stdout),
with these additions: an unbound or wrong-kind handle, a bad `let`, `other` before `builder2`, `builder2` before
`dialect` or twice. The corpus holds no script error.

### The run

`anvil-dump --builder-script <file>` prints, to stdout, ASCII with `\n` line endings and quoted strings written as in the
reader dump:

```
anvil-builder-run 1
<records, one per event, in execution order>
steps N
status ok
```

- **`get_error code=C name=NAME`**, **`error_message code=C text="..."`**: as in the writer run. `get_error` is on the
  builder the step names (`other get_error` is builder 2's).
- **`find line=L result=found`** or **`find line=L result=none`** for each `find` step.
- **`emit bytes=N text="..."`** for each `emit` that succeeded: the document text (the terminating NUL is not counted).
- **`write bytes=N text="..."`** for each `write` that succeeded: the finished writer's data.
- **`failed line=L code=C name=NAME call="..." message="..."`** for each failed call: `call` is the step's line verbatim
  (the `let` and `other` included) with leading and trailing blanks removed; `C` is `anvil_builder_get_error` of the
  builder the call was made on right after the call (for a failed `finish` in `write`, the writer's error);
  `message` is `anvil_writer_error_message(C)`.
- **`steps N`**: the steps executed, the failing one included. A step after a stop is not counted.
- **`status ok`** or **`status error code=C name=NAME`**: `anvil_builder_get_error` of builder 1 at the end.

`anvil-dump --builder-script <file> --emit-dir <dir>` also writes the bytes of the k-th successful `emit` or `write`
step (counting from 1, either builder) to `<dir>/emit-<k>.anvl`; `scripts/check-builder-roundtrip.sh` uses it.

### The builder corpus

`conformance/cases/builder/<area>/<name>.bscript` is a script and `<name>.bscript.dump` is native's run. The scripts are
**generated** by `conformance/seed/gen_builder.py`, which writes scripts only; the runs are native's, written by
`make update-conformance` and by nothing else. `make check-conformance` checks, for every `.bscript`, that native's run
equals the committed `.dump`, and `make check-builder-roundtrip` checks that **every successful `emit` and `write` loads
through the native reader with `status ok`** (an `include` is satisfied by an empty file of that name; known
inconsistencies are listed with their ticket or reason in `conformance/builder-roundtrip-known.txt`). `make check-builder-gen`
checks that the generator reproduces the committed scripts and writes no dump.

Areas: `lifecycle` (new, get_error, error_message, non-sticky errors, emit twice, write), `values` (every value kind and
its errors), `names` (statement names, duplicates), `collections` (arrays, tuples, objects, attaching rules, nesting),
`attributes` (module and member attributes), `include` (include ordering), `bases` (`set_base`, the
INHERITANCE_REQUIRES_OBJECT check across all members), `find`, `depth` (nesting up to and beyond the limit), `amp` (the
AMP dialect and what it refuses), `handles` (null, foreign and misused handles), `envelope` (King & Crucible shaped
documents) and `flywire` (FlyWire shaped documents).

## Drift tables

`conformance/drift-tables.txt` is generated by `scripts/gen-drift-tables.sh` from `include/*.h`, and
`make check-conformance` fails when it is stale. Line format: `drift-tables 1`, then `table <name>` followed
by `key value` lines. Tables: `enum:<typedef>` for every enum in the public headers (error codes

## Running the tool

```
anvil-dump <file>             a file: includes resolve, the extension is the dialect hint
anvil-dump -                  stdin, loaded as a buffer
anvil-dump --fragment <file|->  a standalone value expression
anvil-dump --writer-script <script>   run a writer script ("The writer script", above)
anvil-dump --writer-output <script>   the same, printing only the output bytes
anvil-dump --builder-script <script> [--emit-dir <dir>]   run a builder script ("The builder script", above)
```

Exit status `0` for any dump (including of an input that fails to parse), `2` for a usage or tool error.
`make anvil-dump` builds `build/tools/anvil-dump`.

### The batch protocol

```
anvil-dump --batch            read paths from stdin, one per line; dump each
```

This is how the fuzz harness avoids starting one process per input. A port that is to be fuzzed provides the same mode
(any program that follows the rules below can be side `b`; the harness also has `--no-batch`, which runs
`CMD [--fragment] <path>` once per input).

- **Input**: standard input is a list of file paths, one per line, each ended by `\n` (a final line without one is also
  read). The paths are relative to the process's working directory or absolute, and are opened exactly as the
  single-file mode would open them (so includes resolve against the file's own directory). An empty line is skipped.
  A path ending in `.frag` is dumped as a value fragment (`--fragment`), every other path as a document, whatever its
  extension (the extension is still the dialect hint). Combining `--batch` with a path argument or `--fragment` is a usage error (exit 2).
- **Output**: for each path, in input order, the line `@@ <path>` (the path exactly as read, without its newline)
  followed by that input's complete dump, from `anvil-dump 1` to its last line, as the single-file mode would print it.
  Nothing else is written to standard output between or after dumps: no blank lines, no trailer. The harness splits the
  stream on lines that start with `@@ `. (A dump line can never start with `@@ `: every dump line starts with a
  record name or two spaces of indent.)
- **Errors**: a path that cannot be read is dumped as the unreadable-file dump (`status error`, `error code=0 ...`)
  after its `@@` line, like the single mode, and the run goes on. The exit status is `0` unless a tool error happened
  (`2`). Diagnostics go to standard error and are empty in a healthy run: the harness counts anything written to standard error, a crash, a timeout or a non-zero exit as a difference.
- **State**: each input is loaded in a fresh context, as in single mode: nothing carries over from one input to the next
  (the registry that makes identical bytes one document is per load, so a file included by two *different* inputs is
  not the same document in both dumps).

## Differential fuzzing

`conformance/fuzz/` generates and mutates inputs and compares two executables' dumps; see its `README.md`.
